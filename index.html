📖 How does it work?

This application is a deterministic code generator based on HMAC-SHA-256. All processing takes place locally in the browser.

It is not TOTP and must not be presented as a system for two-factor authentication. Its purpose is to produce the same code for the same combination of inputs every time.

Name ↓ Normalization ↓ Counting letters/vowels/consonants ↓ PIN ↓ BASE calculation ↓ Message ↓ Password as HMAC key ↓ HMAC-SHA-256 ↓ BigInt ↓ Modulo 62¹² ↓ Base62 ↓ Final 12-character code
1. Input data

The system receives three inputs:

  • Name
  • Password
  • PIN of exactly 4 digits

All three values are required to generate the code. There is no default password or PIN.

Name: Generator Password: password123 PIN: 0123
2. Name normalization

Leading and trailing spaces are removed from the name, converted to lowercase and normalized using Unicode.

Input: Generator Result: generator

The normalized result is used in the following steps.

3. Counting letters, vowels, and consonants

The application iterates through the normalized name and considers only characters recognized as Unicode letters.

g e r a d o r

For generator:

Letters: 7 Vowels: 3 Consonants: 4

Therefore:

letters = 7 vowels = 3 consonants = 4
4. PIN interpretation

The PIN defines the multipliers used in the calculation the BASE.

In the example:

PIN = 0123 01 | 2 | 3

The code splits the PIN as follows:

AB = 01 C = 2 D = 3 CD = 23

The values are converted numerically as follows:

AB = 1 C = 2 D = 3 CD = 23
5. BASE calculation

The implemented formula is:

BASE = (letters × AB) + (vowels × C) + (consonants × D) + (AB × CD)

Using the example:

letters = 7 vowels = 3 consonants = 4 AB = 1 C = 2 D = 3 CD = 23

The calculations are:

7 × 1 = 7 3 × 2 = 6 4 × 3 = 12 1 × 23 = 23

Somando:

7 + 6 + 12 + 23 = 48

Therefore:

BASE = 48
6. Message creation

The BASE is combined with the normalized name and PIN into a standardized message.

name=generator|pin=0123|base=48

The format used by the code is:

name=NORMALIZED_NAME|pin=PIN|base=BASE

The message is deterministic: for the same inputs, it will be exactly the same.

7. Password as the HMAC key

The password is not simply concatenated to the message. It is used as the HMAC cryptographic key.

Key: password123 Message: name=generator|pin=0123|base=48 Algorithm: HMAC-SHA-256

The application uses the browser-native Web Crypto API through crypto.subtle.

8. HMAC-SHA-256

The browser calculates HMAC-SHA-256 using the password as the key and the message as the authenticated content.

password123 + name=generator|pin=0123|base=48 ↓ HMAC-SHA-256 ↓ 32 bytes

SHA-256 produces a 256-bit result, which corresponds to 32 bytes.

9. Conversion to BigInt

The 32 bytes produced by HMAC are interpreted as a single positive integer using BigInt.

32 bytes ↓ BigInt

This allows the required numeric conversion to be performed without relying on the limited precision of standard JavaScript numbers.

10. Modulo 62¹²

To limit the result to the space of possible codes with exactly 12 Base62 characters, the number is reduced using modulo 62¹².

BigInt ↓ BigInt % 62¹²

This step keeps the result within the range required to represent 12 Base62 positions.

11. Base62

The number is converted using 62 symbols:

ABCDEFGHIJKLMNOPQRSTUVWXYZ abcdefghijklmnopqrstuvwxyz 0123456789

There are 26 uppercase letters, 26 lowercase letters, and 10 digits, for a total of 62 characters.

12. Final code

The conversion is performed until exactly 12 characters are formed.

HMAC-SHA-256 ↓ BigInt ↓ modulo 62¹² ↓ Base62 ↓ 12 characters

If the representation needs additional characters to fill the 12 positions, the algorithm fills the leading positions with the first symbol of the Base62 alphabet.

13. Determinism

The system does not use random numbers, dates, or time.

Therefore, when keeping exactly the same inputs:

Name: Generator Password: password123 PIN: 0123

the steps will produce the same message, the same HMAC and the same final code.

same inputs ↓ same BASE ↓ same message ↓ same HMAC ↓ same code

Changing the name, password, or PIN changes the input to the process and consequently changes the expected result.

14. Automatic update

The generator monitors changes to all three fields. When Name, Password, or PIN is modified, a new generation is started.

Name changed ↓ new generation Password changed ↓ new generation PIN changed ↓ new generation

Processing continues to occur only in the browser.

15. Protection against stale results

HMAC is calculated asynchronously. Therefore, a rapid change to the fields could start multiple calculations at the same time.

The application assigns an identifier to each generation. When a calculation finishes, its identifier is compared with the latest generation identifier.

Generation 1 started ↓ user changes the inputs ↓ Generation 2 started ↓ Generation 2 finishes ↓ Generation 1 finishes later ↓ Generation 1 result is ignored

Thus, an old calculation cannot replace the most recent result.

🔒 Security and privacy

Processing is performed 100% locally in the browser.

The application does not send Name, Password, PIN, or code to any server.

It does not use a database, external API, or third-party service.

Password and PIN are not stored in localStorage or sessionStorage.

The system does not use Math.random(), date, time, or TOTP.

The browser Web Crypto API is used to perform HMAC-SHA-256.

⚠️ Important

This application is a deterministic code generator based on HMAC-SHA-256.

It is not TOTP and must not be considered a two-factor authentication authentication system.

This project does not replace professional authentication mechanisms, credential management, or security systems specifically developed for this purpose.

16. Complete example
